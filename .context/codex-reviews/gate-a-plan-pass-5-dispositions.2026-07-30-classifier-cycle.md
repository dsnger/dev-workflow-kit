1. BLOCKER `{ : > "$marker"; }` exits `dash` on a redirection failure — ACCEPT, verified in-session and worse than reported. `:` is a POSIX **special builtin**: with a directory at the target, `{ : > m; } 2>/dev/null || true; echo REACHED` prints nothing and exits **2** under `dash`, while the `printf` form prints `REACHED` and exits 0. `/bin/sh` on Ubuntu — which CI runs — is `dash`. **This is a live defect in the shipped hook**, not only in the plan: `codex-gate.sh:394` already uses that form, so on Linux an unwritable `.context/` makes the hook exit 2 from the unknown-tool branch — a direct violation of invariant 1. All four writes converted to `printf '%s' ''`, the pre-existing line is fixed in Task 4, and the marker faults are asserted under `dash` as well as `sh`. The existing "special-builtin redirection regression" test only ever ran under macOS `sh`, where the form happens to survive, which is why this stood.
